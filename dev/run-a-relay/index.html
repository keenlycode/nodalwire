Run a relay

Start a local relay, inspect its configuration, and administer networks deliberately.

Start your relay

Install NodalWire 0.3.0 as described in Get started, then supply an administrator token and run the relay in the foreground:

terminal 1shell
export NODALWIRE_ADMIN_TOKEN="$(python3 -c 'import secrets; print(secrets.token_urlsafe(32))')"
nodalwire serve

Leave this terminal open. The relay reports its data endpoint after binding; the default data endpoint is tcp://127.0.0.1:5555, and administration uses the separate tcp://127.0.0.1:5556. Do not start another relay on ports already in use. Press Ctrl-C to stop your relay when finished.

Without a configuration file, administrative changes are memory-only. To persist supported policy changes, start with serve --config local.toml; see the version 2 configuration reference for a valid file and persistence boundaries. Endpoints and native limits are startup-only.

Administration: create a network

In a second terminal, make the same administrator token available securely as NODALWIRE_ADMIN_TOKEN; do not paste it into a command or share it as a network join token. Read the current revision first:

terminal 2shell
nodalwire admin config.get

The JSON response includes the current revision and redacted configuration, not bearer values. On a relay without a team network, replace REVISION below with the observed integer. This creates a protected network using a separate generated join credential:

terminal 2shell
export TEAM_JOIN_TOKEN="$(python3 -c 'import secrets; print(secrets.token_urlsafe(32))')"
nodalwire admin network.create \
  --network team --credential-env TEAM_JOIN_TOKEN --expected-revision REVISION
nodalwire admin member.list --network team

The create response identifies team as protected and reports the new revision. The member list is initially empty if no one has joined. Give the join credential to authorized applications through a trusted local channel; each must explicitly join team. It grants join permission, not identity or administrator authority. See networks and membership for client examples.

If the revision has changed, reconsider your intended operation against current state; do not blindly retry. A timeout can also follow a mutation, so read and reconcile the state before deciding what to do. Configuration-file commits can have indeterminate persistence outcomes; consult the exact reference.
