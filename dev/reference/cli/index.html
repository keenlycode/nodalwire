CLI reference

A foreground relay and bounded one-shot client/admin commands, with structured output and no retries.

Invoke the installed CLI

Use nodalwire from the CLI installation in Getting started. Append --help to any command for the full generated option list. These commands assume matching installed artifacts and your own relay. Contributors in a locked checkout may instead use uv run --locked python -m nodalwire.

terminalshell
nodalwire --help
nodalwire serve --help
nodalwire send --help

Each client invocation registers a new connection and explicitly joins the selected network, then disconnects. A later invocation does not inherit membership, pending requests, or an inbox. Use the Python/Node clients for persistent service loops.

Relay: serve

serve [--config PATH] runs in the foreground. Invoking nodalwire without a subcommand shows help and exits; use serve explicitly to start the relay. Supply NODALWIRE_ADMIN_TOKEN explicitly, or a valid configuration verifier; missing/malformed credentials fail before bind. The service prints its data endpoint after native bind succeeds.

serve has no --endpoint option. Set data/admin endpoints in strict version 2 TOML. Without a file the configuration is memory-only; with --config, administration saves policy changes to that same file. Endpoints and native limits are startup-only.

terminalshell
export NODALWIRE_ADMIN_TOKEN="$(python3 -c 'import secrets; print(secrets.token_urlsafe(32))')"
nodalwire serve --config local.toml

See configuration for a safe file and security for credential handling.

Peer commands

send DESTINATION --name NAME
Sends stdin bytes once, or uses --input-file PATH. Successful completion means native queue acceptance only.
receive --name NAME
Receives --count messages (default 1), then disconnects. Emits a ready event after joining, message events, then completion. No continuous mode.
request DESTINATION --name NAME
Reads stdin/file bytes, holds this connection for a correlated reply, then disconnects. Emits unrelated ordinary messages rather than discarding them. A reply or cutoff ends the operation.
reply --name NAME --request-file PATH
Reads new reply bytes from stdin/file and exactly one prior six-key message event from the request file. Joins its incoming network on a new connection and replies there. The requester must still be connected, and the replying name must match the name it expected.

Common options are --endpoint (default tcp://127.0.0.1:5555), --join-token-env VARIABLE, and --timeout (default 5 seconds). Send, receive, and request accept --network (default only; no fallback). Reply selects the network from the request event instead.

The deadline includes input reading, connecting, joining, and the operation. Release cleanup has a separate bounded attempt of up to 0.2 seconds. Join credentials are passed by environment-variable name, never as bearer values on the command line.

Input commands default --max-bytes to 1,048,576. Receive defaults --max-output-bytes to 2,097,152 for message JSON. Request defaults --max-unrelated to 64 and --max-output-bytes to 1,048,576 for unrelated events; its terminal reply has a separate bounded JSON budget. Reaching an output cutoff is an explicit uncertain outcome, not proof of no effect.

For an open default, run the receiver in one terminal, wait for its ready event, then send from another:

two terminalsshell
# Terminal A: keep this invocation open until a message arrives.
nodalwire receive --name bob --timeout 30

# Terminal B, after Bob reports ready:
printf 'hello' | nodalwire send bob --name alice

There must already be a separately running matching relay with its explicit startup administrator credential. A nondefault network must already be declared; select it on both commands and supply join credentials if protected.

Output and exit status

Client/admin output is newline-delimited JSON on stdout; safe structured errors are written to stderr. Message and reply payloads are canonical base64 strings, not UTF-8 text or raw binary stdout. Every message event has exactly event, id, reply_to, network, sender, and payload; absent reply_to is explicit JSON null. A request's terminal reply uses event:"reply" and exposes the reply ID and referenced request ID. Send/reply accepted events include their generated ID and reply_to only after queue acceptance. Preserve exactly one message event for reply --request-file, not the whole ready/completion stream. The file parser rejects missing/unknown/duplicate keys, malformed metadata, noncanonical base64, nonfinite JSON, and wrong event types before connecting.

Successful operations exit 0. Runtime/rejection/deadline failures exit 1; invalid input/configuration exits 2; interrupt exits 130. Errors include safe codes and an outcome such as no_effect or indeterminate. A release failure after a result was emitted is reported separately; do not reinterpret it as undoing that result.

A timeout, cancellation, output cutoff, I/O failure, or lifecycle interruption may follow an effect. Never infer retry safety from a nonzero exit alone. No command automatically retries, reconnects, or replays.

NodalWire 0.3.0 is a breaking wire/API upgrade, not a 0.2.x patch. Use a matching 0.3.0 relay and regenerate saved receive events; old four-key event files are rejected. Remove envelope decoding and use raw payload bytes plus native message IDs/reply_to. NA1 administration and configuration version 2 are unchanged.

Administration

admin OPERATION uses the separate endpoint (default tcp://127.0.0.1:5556). Common options: --endpoint, --token-env (default NODALWIRE_ADMIN_TOKEN), --timeout, and explicit --expected-revision for every mutation. Operation-specific arguments include --network, --member, --protected/--no-protected, and --credential-env for a new join/admin credential.

Use dotted operations, not invented subcommands: config.get, network.list, network.get, network.create, network.update, network.rotate, network.delete, member.list, member.remove, and admin.rotate. See administration for arguments, revisions, and persistence cutoffs.
