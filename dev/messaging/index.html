Messaging

Send bytes, receive messages, and understand what a reply tells you.

A message carries your bytes

Choose a destination and a network. The relay routes your payload as opaque bytes: it does not parse JSON or decide what your message means. A received Message also includes an ID, sender, network, and optional reply_to. Names are routing labels, not proof of identity.

Both applications need to be connected and members of the selected network. The open default network is joined automatically; other networks require an explicit join. See networks and membership.

Send and receive

With a matching relay running and Bob already connected, this Python example sends one message. It uses the open default network. Follow Get started for a complete two-process exchange and cleanup.

send.pypython
import asyncio
from nodalwire import Node

async def main():
    async with await Node.connect("alice") as alice:
        message_id = await alice.send("bob", b"hello")
        print("queued:", message_id)

asyncio.run(main())

On success, the output starts with queued: followed by a generated message ID. The context manager closes Alice's connection. Bob must be online, joined, and permitted by routing policy; otherwise sending can fail. A successful send confirms relay native per-destination queue acceptance only, not Bob's receipt or processing.

A connected Bob can read message = await bob.receive() and inspect message.payload. In Node.js use await bob.receive() and a Uint8Array payload; see the API reference for lifecycle and timeout details.

Ask for an application reply

For connected Python nodes, response = await alice.request("bob", b"question", timeout=5) waits for a matching reply; Bob can respond with await bob.reply(incoming, b"answer"). Run Bob's receiver concurrently. The reply confirms only what Bob's application chose to acknowledge; it is not identity proof or a guarantee of durable business work.

The request/reply guide has runnable Python and Node examples, matching rules, and inbox guidance.

Handle uncertain outcomes

A timeout or cancellation may occur after a message was queued or another effect happened. Do not assume failure means nothing happened, and do not blindly retry a mutation. NodalWire supplies no automatic retry, reconnect, replay, or durable-delivery guarantee. Design application acknowledgements and idempotency for the effects that matter to you.

Keep consuming ordinary messages while waiting for requests: a full inbox can pause the reader and delay replies or control progress. Consult API errors and lifecycle for exact limits.
