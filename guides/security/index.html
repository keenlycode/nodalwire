Security and local trust

NodalWire is a cooperative, same-machine byte relay—not an identity service or encrypted network.

Loopback is a boundary, not a sandbox

Data and administration endpoints accept only loopback TCP addresses: literal IPv4/IPv6 or localhost, which is normalized without DNS. Wildcard hosts, remote hosts, and arbitrary DNS names are rejected. A wildcard port is allowed only when binding a relay, not when connecting a client.

Local bearer authentication is not encryption. It does not protect traffic or credentials from a sufficiently privileged local process, root, or same-user memory inspection. Do not expose the service through a port forward or assume that network credentials isolate mutually hostile local users. No security-audit or production-hardening claim is made.

Routing names are not identities

A peer chooses an ephemeral name that is unique for its live registration. A name, an allowed_names admission list, a routing group, and a message's relay-supplied sender field do not authenticate a person or agent. Another process may claim a name after release or lease expiry.

Request/reply IDs correlate traffic with a pending operation; they do not establish identity. Never grant additional authority merely because a payload, sender label, or routing-group selector claims it.

Keep the two authorities separate

Administrator credential
Authenticates each operation on the separate administration endpoint. Startup requires an explicitly supplied NODALWIRE_ADMIN_TOKEN or a valid configured admin_verifier. Nothing generates or prints an administrator token automatically.
Network join credential
Authorizes a join to a protected network. It grants neither name ownership nor administration rights. An administrator token is not implicitly a network join credential.

Use distinct high-entropy values for these roles. Token syntax is 1–1024 printable ASCII characters without spaces or control characters. Store verifiers rather than raw bearer values in configuration. The current verifier format is salted scrypt-v1; it still does not encrypt transport.

Generate and explicitly export an administrator credential before starting your own relay:

terminalshell
export NODALWIRE_ADMIN_TOKEN="$(.venv/bin/python -c 'import secrets; print(secrets.token_urlsafe(32))')"
.venv/bin/nodalwire serve --config local.toml

Protect the terminal environment and configuration file. Avoid command-line bearer values, shell history containing literal secrets, logs, or copied screenshots. The CLI's --token-env, --join-token-env, and --credential-env flags name environment variables, not token values. Configuration reads redact verifiers; do not interpret redaction as immunity to local inspection.

Understand policy cutoffs

Networks are open unless protected. Open default autojoins; protected default requires explicit joining, and all nondefault networks require explicit joining even when open. Both peers must be members of the selected network. Directional deny rules can further restrict routing.

Protecting a network or rotating its join credential changes future joins, including repeated joins. It does not evict existing members. member.remove removes one current membership, but a process with a still-valid credential may join again. Deleting a nondefault network removes its memberships; recreating it does not restore them. The reserved default network cannot be deleted.

No policy change recalls data already accepted by native queues. If an operation times out or is canceled, its effect may already have happened. Read state and reconcile deliberately instead of blindly retrying. An environment-managed administrator credential cannot be rotated by the API; change startup configuration/environment and restart under your own operational controls.

Use matching protocol versions

Released 0.2.x artifacts use AR2 transport and strict config_version = 2; released wire/configuration incompatibilities are rejected, not silently downgraded. NWM3 is a separate breaking wire/API migration tracked as a coordinated 0.3 candidate, not a published-availability claim or a 0.2.x patch. NWM3 clients and relays must match. NA1 administration and configuration version 2 remain unchanged. Under NWM3, old NWR1-marked bytes are opaque application payload, never auto-detected or decoded.
