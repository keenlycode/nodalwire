Administration reference

Separate local bearer authority, explicit revisions, and no automatic mutation replay.

Start with explicit authority

Relay startup requires an explicitly supplied NODALWIRE_ADMIN_TOKEN or configured admin_verifier. No token is automatically generated. An environment token overrides the verifier and makes administrator rotation environment-managed. Use a different credential for protected network joins.

Administration uses its own loopback endpoint, default tcp://127.0.0.1:5556; peer data defaults to port 5555. Bearer authentication is not encryption or peer identity. The Python AdminClient does not register a peer; connecting only opens transport, while each call authenticates separately. There is no Node admin client.

Read, then mutate with the observed revision

This function accepts the actual administration endpoint and explicit startup credential. On a fresh relay without a team network it creates an open network. The caller supplies the credential from its protected environment, not a source-code literal.

admin.pypython
from nodalwire import AdminClient

async def create_team(admin_endpoint, admin_token):
    async with await AdminClient.connect(admin_endpoint, token=admin_token) as admin:
        current = await admin.call("config.get")
        created = await admin.call(
            "network.create", {"network": "team"},
            expected_revision=current.revision,
        )
        assert created.revision == current.revision + 1
        assert created.result == {"network": "team", "protected": False}
        return created

AdminClient.connect(endpoint=..., *, token, timeout=5.0) returns an owned client. call(op, args=None, *, expected_revision=None, timeout=None) returns AdminReceipt(revision, result). Timeouts are finite positive seconds, defaulting to the client setting. One call at a time is allowed; overlapping calls reject pending_full. Context exit/close cleans up its socket and context.

Every mutation requires a nonnegative integer expected revision through 2**53 - 1. Reads reject an expected revision. A stale mutation fails revision_conflict; do not automatically read/retry, because the new state may change what you intended.

Operations and argument objects

config.get {}
Returns redacted startup/configuration fields, network protection flags, admin_source, and admin_configured. No bearer values or verifiers.
network.list {}
Returns a sorted networks array of { network, protected }.
network.get {network}
Returns that network's name and protection flag.
member.list {network}
Returns the network and sorted live member names. These are routing labels, not authenticated identities.
network.create {network, credential?}
Creates an open network when credential is omitted; otherwise creates it protected with a verifier of that join credential. Existing network rejects network_exists.
network.update {network, protected, credential?}
Requires an explicit boolean policy. Making an open network protected requires a credential; an already protected network can retain its verifier when no new credential is supplied. Making it open forbids a credential.
network.rotate {network, credential}
Replaces the join verifier of an already protected network. An open network rejects invalid_policy.
network.delete {network}
Deletes a nondefault network and removes its memberships. Deleting reserved default rejects reserved_network. Recreating a name does not restore memberships.
member.remove {network, name}
Removes a current membership; returns changed and ephemeral: true. Requires the current expected revision, but does not increment it or write a configuration commit.
admin.rotate {credential}
Changes a configuration-managed administrator verifier. Environment-managed authority rejects environment_managed. Use the new credential for subsequent calls.

All operations except the four reads above are mutations. Argument keys are exact; unexpected fields are rejected. Configuration commits increment revision even when the resulting policy is equivalent. Protection changes and join-token rotation govern future joins, not existing members or already accepted data.

CLI control

The default token variable is NODALWIRE_ADMIN_TOKEN. Read first, then substitute the observed integer for REVISION. A changed revision is a reason to reconsider the operation, not a cue for a blind loop.

terminalshell
uv run --locked python -m nodalwire admin config.get
uv run --locked python -m nodalwire admin network.list
export TEAM_JOIN_TOKEN="$(uv run --locked python -c 'import secrets; print(secrets.token_urlsafe(32))')"
uv run --locked python -m nodalwire admin network.create \
  --network team --credential-env TEAM_JOIN_TOKEN --expected-revision REVISION
uv run --locked python -m nodalwire admin member.list --network team

--token-env VARIABLE selects the current administrator credential; --credential-env VARIABLE selects a new join/admin credential. Both name variables, not bearer values. network.update requires --protected or --no-protected. member.remove maps --member NAME to the name argument. --endpoint selects the separate administration endpoint. See CLI output and exit status.

Errors and persistence outcomes

AdminError subclasses RelayError and exposes safe code, outcome, and revision. Rejections include unauthorized, invalid_request, revision_conflict, network_not_found, network_exists, reserved_network, invalid_policy, credential_required, environment_managed, persistence_failed, and response_too_large, normally with outcome="no_effect".

persistence_indeterminate instead has outcome="indeterminate": replacement may have happened but durability could not be established. Timeouts/cancellation can also follow an accepted mutation; a ReceiptTimeout does not prove no effect. A response-size rejection cannot be used to recall a previously selected effect. Read and reconcile state deliberately rather than replaying a mutation.

Without a config path, changes are memory-only. With serve --config, commits rewrite the same regular file; comments/formatting are not retained, and external edits can cause conflicts. See configuration and persistence for startup-only fields and file boundaries. Credential rotation never encrypts transport or recalls accepted data.
