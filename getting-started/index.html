Getting Started

Build and install matching local NWM3 development artifacts, then exchange native messages between Node.js and Python.

1. Set up

This walkthrough targets the coordinated NWM3 development candidate, not a published release. Use the same ROOT-reviewed assembled NWM3 source checkout to build both local artifacts. The development labels are Python 0.3.0.dev0 and Node 0.3.0-dev.0; they identify local candidate builds only and make no claim of registry availability. Released Python 0.2.x / Node 0.2.0 artifacts use AR2 and are incompatible with NWM3. You need Python 3.12+, Node.js 24, uv, and pnpm 12.5.1.

build local candidate artifactsshell
# From the reviewed, assembled NWM3 source checkout:
uv sync --locked
pnpm --dir src/nodalwire/client/node install --frozen-lockfile
pnpm --dir src/nodalwire/client/node exec tsc -p tsconfig.json
mkdir -p /tmp/nodalwire-nwm3-candidate
uv build --out-dir /tmp/nodalwire-nwm3-candidate
pnpm --dir src/nodalwire/client/node pack --pack-destination /tmp/nodalwire-nwm3-candidate

Confirm both outputs came from that same reviewed checkout. Then create a separate application directory and install the local files; do not install by package name or overwrite an existing application's pnpm script policy:

install local candidate artifactsshell
mkdir my-nodalwire-app
cd my-nodalwire-app
uv venv .venv
uv pip install --python .venv/bin/python /absolute/path/nodalwire-0.3.0.dev0-py3-none-any.whl
printf 'allowBuilds:\n  zeromq: true\n' > pnpm-workspace.yaml
pnpm add /absolute/path/devcapsule-nodalwire-client-0.3.0-dev.0.tgz

Replace the local artifact paths with the files built above. Run the remaining walkthrough commands from this application directory. These shell paths are for Linux/macOS; local verification covered Linux only. Do not substitute released 0.2.x artifacts for either NWM3 dependency.

About the Node.js setup

The local tarball includes compiled JavaScript and declarations; consumers need neither Deno nor TypeScript. The native zeromq install script is required and explicitly permitted above. Native prebuild/fallback build availability is platform-dependent; other package managers have different script policies. Contributor builds and maintainer artifact acceptance are separate steps described in the repository README. Building or installing these local candidate files does not publish them or establish registry availability.

2. Start the relay — Terminal 1

Create a private administrator token, then start the relay. Leave it running.

terminal 1shell
export NODALWIRE_ADMIN_TOKEN="$(.venv/bin/python -c 'import secrets; print(secrets.token_urlsafe(32))')"
.venv/bin/nodalwire serve

The token is required to start the relay, but these clients do not need it. This example uses the default local endpoint and an open default network. Do not start a second relay if one is already using these ports, or connect these clients to a released AR2 relay. For a separate instance, use .venv/bin/nodalwire serve --config relay.toml with unused loopback data/admin ports in a v2 configuration. Set NODALWIRE_ENDPOINT to its data endpoint in both client terminals.

3. Run Python — Terminal 2

Save this as python-echo.py in your application directory.

python-echo.pypython
import asyncio
import os

from nodalwire import Node


async def main():
    endpoint = os.getenv("NODALWIRE_ENDPOINT", "tcp://127.0.0.1:5555")
    async with await Node.connect("python-echo", endpoint) as echo:
        print("Python is ready", flush=True)
        message = await asyncio.wait_for(echo.receive(), timeout=120)
        print(message.payload.decode())
        await echo.send(message.sender, b"hello from Python")


asyncio.run(main())

Open a second terminal and run:

terminal 2shell
.venv/bin/python python-echo.py

Wait for Python is ready, then run Node.js in the next step.

4. Run Node.js — Terminal 3

Save this as node-exchange.mjs in your application directory.

node-exchange.mjsjavascript
import { Node } from "@devcapsule/nodalwire-client";

const endpoint = process.env.NODALWIRE_ENDPOINT ?? "tcp://127.0.0.1:5555";
const client = await Node.connect("node-client", endpoint);
try {
  await client.send("python-echo", new TextEncoder().encode("hello from Node"));
  const reply = await client.receive({ signal: AbortSignal.timeout(5000) });
  console.log(new TextDecoder().decode(reply.payload));
} finally {
  await client.close();
}

Open a third terminal and run:

terminal 3shell
node node-exchange.mjs

Python prints hello from Node and Node.js prints hello from Python. Both clients then exit; the relay stays running. Press Ctrl-C in Terminal 1 when you are finished with your relay.

If the exchange does not finish

Python waits up to two minutes for the message; Node.js waits up to five seconds for the reply. If either times out, check the relay, restart Python, wait for its readiness line, then run Node.js again. These examples use 127.0.0.1:5555 unless NODALWIRE_ENDPOINT is set. An existing protected network needs a join credential; see the networks guide.

Next steps

You have exchanged bytes between two local applications. The reply confirms that Python handled the message; sending alone does not confirm processing. Continue with networks, request/reply, or the API reference. Read security before sharing credentials: they grant permission, not peer identity or encryption.
