Registration is not membership

A node registers one live routing name. It can then belong to several declared networks. Names are unique while registered, not authenticated identities. Configuration declares network policies, not lists of permanently joined peers.

  • An open default network is joined automatically at registration.
  • A protected default allows registration with zero memberships. Each peer must explicitly join it with the join credential.
  • Every nondefault network requires an explicit join, even when open.
  • Both sender and destination must belong to the selected network. Omit the selector and you choose default only: there is no fallback to another shared network.

Use an open network

Add this table to a version 2 configuration, then start the relay with an explicit administrator credential as in Getting Started.

{% set open_config %}config_version = 2 [networks.team] {% endset %}{{ code_block(open_config, 'local.toml', 'toml') }}

The following Python function uses two already-connected Node instances. Call await exchange_open(alice, bob) while both connections remain open.

{% set open_example %}import asyncio async def exchange_open(alice, bob): await alice.join("team") await bob.join("team") await alice.send(bob.name, b"hello\x00", network="team") incoming = await asyncio.wait_for(bob.receive(), timeout=5) assert incoming.sender == alice.name assert incoming.network == "team" assert incoming.payload == b"hello\x00" return incoming {% endset %}{{ code_block(open_example, 'open_network.py', 'python') }}

In Node.js the same operations are await alice.join("team") and await alice.send(bob.name, bytes, { network: "team" }). Use Uint8Array or Buffer payloads.

Protect joins, including the default

An administrator can create a protected network or change default to protected using network.update. Generate a separate join credential and pass its environment-variable name, not its value, to the CLI. Read the current revision first; replace REVISION with that returned integer.

{% set protect_commands %}.venv/bin/nodalwire admin config.get export TEAM_JOIN_TOKEN="$(.venv/bin/python -c 'import secrets; print(secrets.token_urlsafe(32))')" .venv/bin/nodalwire admin network.update \ --network default --protected --credential-env TEAM_JOIN_TOKEN \ --expected-revision REVISION {% endset %}{{ code_block(protect_commands, 'terminal', 'shell') }}

For peers connecting after this change, registration still succeeds but does not autojoin the protected default. Supply the same join credential through a trusted local channel; it grants join permission, not ownership of either name.

{% set protected_example %}import asyncio async def exchange_protected(alice, bob, credential): await alice.join("default", credential) await bob.join("default", credential) await alice.send(bob.name, b"joined", network="default") incoming = await asyncio.wait_for(bob.receive(), timeout=5) assert incoming.network == "default" assert incoming.payload == b"joined" return incoming {% endset %}{{ code_block(protected_example, 'protected_default.py', 'python') }}

Node.js also takes the credential positionally: await alice.join("default", credential). Administrator and join credentials are separate authorities; do not treat one as the other.

Leave and inspect outcomes

await alice.leave("team") removes only that membership. Join and leave return { network, joined, changed } receipts. Repeating a successful join or an absent leave returns changed: false; a repeated join still checks the current policy. A receipt describes an instant, not a permanent membership guarantee. Administrators can remove members.

Useful safe rejection codes are network_not_found, join_denied, not_member, and destination_not_member. A timeout is different: the effect may already have occurred, so do not blindly replay it.

Membership does not override routing policy

Directional deny rules can block sends even between members. Selectors are exact routing names, @group references to static routing_groups, or *. A rule from Alice to Bob does not also deny Bob to Alice. Groups are selectors, not memberships or identities; unspecified routes are allowed.

Protection and credential rotation affect future joins. Existing members remain admitted until they leave, disconnect, expire, or are removed. Already accepted data is not recalled. See administration and security limits.
