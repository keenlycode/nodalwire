Get started

Install NodalWire, start a local relay, and send your first message.

You will send hello between two terminals on your computer. You only need the NodalWire command-line tool for this walkthrough—no application code, Node.js setup, or source build.

This quick start is for NodalWire 0.3.0. Use that same version in all three terminals, including the relay. Version 0.2.x cannot communicate with a 0.3.0 relay.

1. Install NodalWire

You need Python 3.12 or later and uv. Install the command-line tool in its own environment:

install NodalWireshell
uv tool install 'nodalwire==0.3.0'
nodalwire --version

These commands use a Linux/macOS-style shell. Open three terminals before continuing, and check that nodalwire --version reports 0.3.0 in each one.

2. Start the relay — Terminal 1

The relay passes messages between your applications. Generate a private administrator token, then start it:

terminal 1shell
export NODALWIRE_ADMIN_TOKEN="$(python3 -c 'import secrets; print(secrets.token_hex(32))')"
nodalwire serve

Leave this terminal running. You should see tcp://127.0.0.1:5555 and a serving status event. No configuration file is required.

Keep the token private. It protects relay administration; you do not need to copy it into the other terminals for this example. The relay uses an open default network and listens only on your computer.

3. Wait for a message — Terminal 2

Name this receiver bob and wait for one message:

terminal 2shell
nodalwire receive --name bob --timeout 60

Wait until you see an event with "event":"ready", then continue to Terminal 3. The receiver will wait for up to 60 seconds.

4. Send hello — Terminal 3

Send a message to bob, using alice as the sender:

terminal 3shell
printf 'hello' | nodalwire send bob --name alice

Terminal 3 prints an accepted event. In Terminal 2, you should see a message event with sender alice and payload aGVsbG8=, followed by a complete event. That payload is simply hello encoded as base64: the CLI uses JSON so it can display binary messages as well as text.

You have sent your first message. accepted means the relay queued it; the message event shows that Bob received it. Neither event promises that an application processed it or stored it permanently.

Both client commands exit after this exchange. To try again, restart the receiver, wait for ready, then send another message. When you are finished, press Ctrl-C in Terminal 1 to stop your relay.

If something does not work

nodalwire is not found
Run uv tool update-shell, then open a new terminal and check nodalwire --version again.
The relay will not start
Run the token-generation command in the same terminal as nodalwire serve. If either default port (5555 or 5556) is already in use, do not stop an unfamiliar process. See Run a relay for choosing other ports.
The message times out or Bob is unavailable
Keep the relay running and make sure all terminals use version 0.3.0. Restart Terminal 2's receiver and wait for ready before sending. These commands all use the same default local relay; an existing protected network needs its own join credential.

For command options, run nodalwire --help or nodalwire receive --help.

Where next?

Connect your apps when you are ready to use NodalWire from a program, or read Messaging to learn about sending, receiving, and waiting for replies. Check the version requirements there before adding an SDK to this setup; the matching Node package is also 0.3.0.
